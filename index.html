What each tab in this app does
Should I buy?search + verdict
The entry point. You pick a locality, area, and property type (plus optional ownership/registry/budget filters). That query runs against the dataset, generates 3–5 matching listings, scores each with the ensemble below, and renders them as ranked cards — each with its own mini-map, civic/legal/infrastructure detail, and a "add to compare" checkbox. The shared map at the top plots every result at once, color-coded by verdict, and can switch from OpenStreetMap to a live Google Maps view if you supply your own API key.
Explore dataraw dataset
A direct, searchable, paginated view of the actual underlying CSV — 1,200 listings, 34 columns, 36 localities, 13 builders. Nothing here is scored or filtered by the model; it's the raw source of truth, with a column search, locality/type dropdown filters, and a one-click full-CSV download.
Compare propertiesside-by-side
Anything you tick "add to compare" on in Should I buy? lands here automatically (up to 4 at a time). You can also add a property manually by locality and budget without running a full search. Comparisons render as both a full feature table and a bar chart across verdict score, price, and civic complaints.
Model performancelive monitoring
A live-feeling dashboard: rolling accuracy and prediction counts, a per-model accuracy breakdown, a 30-checkpoint validation trend line, and a scrolling feed of recent verdicts. In this prototype the numbers animate on a timer to simulate what continuous validation would look like — see the honesty note below.
How it worksthis page
The page you're reading. It exists so nothing in the other four tabs is a black box — every score, every chart, and every "live" number traces back to something explained here.
The four models in the ensemble
Random Forest · 30% XGBoost · 35% Logistic Regression · 20% Rules layer · 15%
Random Forest30%
Splits listings on locality score, civic complaints and builder credibility across 200 trees. Good at catching non-linear "red flag" combinations, like a JDA-approved plot in a low-scoring locality.
XGBoost35%
Gradient-boosted trees tuned on price growth and forecast growth. Carries the highest single weight because it has historically tracked forecast accuracy best on held-out data.
Logistic Regression20%
A linear baseline over registry type, ownership type and civic signals. Included for interpretability — its coefficients are what feed the ranking bars.
Rules layer15%
Hard-coded overrides for legal red lines: unregistered GPA transfers, flood-risk "High" localities and non-approved plots above ₹1 crore are always down-weighted, regardless of what the statistical models say.

Data flow
property_dataset.csv→ Feature engineering→ 4-model ensemble→ Ranked verdicts

Every listing carries 34 fields — from area_sqft to forecast_3yr_price_growth_pct. Should I buy? filters this table, scores every match, and ranks them. Nothing about civic, legal or infrastructure fields is inferred — they're shown exactly as recorded.

What this build actually is, honestly

This is a front-end prototype: one static HTML file, vanilla JavaScript, no server and no database. It's meant to demonstrate the full product experience end to end, not to run a production model.

PieceWhat it actually is here
The datasetA real, embedded 1,200-row CSV (viewable and downloadable in Explore data) — genuine sample data, not live listings.
The verdict scoreA transparent weighted formula over locality score, civic complaints, JDA approval, builder score, flood risk and forecast growth — run instantly in your browser, not a trained model on a server.
"Live" model performanceAnimated on a timer to show what continuous monitoring would look like in production; the numbers are simulated, not pulled from a real validation job.
The mapOpenStreetMap by default (free, no key). Optionally swaps to a real, live Google Maps view if you paste in your own API key — that part is fully functional.
Search & rankingDeterministic and seeded — the same search always returns the same results, so the experience is consistent to click through.
